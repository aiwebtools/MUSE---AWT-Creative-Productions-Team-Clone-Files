# 09 — Team Protocol: One Unit (Kenneth, Nov 4 2026)

Kenneth's order: every team member knows exactly what the other members are doing; the floor works as one functioning unit — excellence and proficiency, mechanically perfect. This file is how.

## The shared board
- `~/workspace/plans/FLOOR_BOARD.md` is the single live board: every lane's current item, state, queue, and gates.
- Every agent READS the board + its project STATUS.md (including PARENT FEEDBACK) before starting work.
- Every agent UPDATES its lane's board lines and its project STATUS.md at start, at each milestone, at handoff, and at completion.
- Board state must match disk state. The watchdog verifies this every ~30 minutes; a board line claiming progress the files don't show is a defect.

## The handoff chain
- Book line: WRITER → AUDIOBOOK → FINISHING, the writer starting the next volume the moment one closes (Handoff Chain Law, Blueprint 01).
- Music-video line: GENERATION → BUILD → PARENT QA → POSTING (one window owns one platform for one video).
- Every handoff is WRITTEN: the receiving member starts from the sender's note in the project STATUS.md — what's done, exact paths/IDs, what remains, flags. Nothing is handed off by implication.

## All product types in parallel (Kenneth, Nov 4 2026)
Music videos, chapter books, audiobooks, picture books, comics, and coloring books all carry work IN PRODUCTION AT THE SAME TIME. A product type idle with queued work is a production failure. Heavy renders still run one at a time inside the video line; the parallelism is across product types and pipeline stages.

## Auto-refire + notify (Kenneth, Nov 4 2026)
An agent that dies on a provider/infrastructure error is re-fired immediately from its checkpoint — no permission asked. Kenneth is told in one breath: it happened, it has already been re-fired and started again, and it will be up shortly.

## The daily rhythm
- **06:30 ET — Daily production handoff:** every lane receives its course of action for the day; idle lanes are fired.
- **Every ~30 min — Watchdog:** stall detection (no agent activity AND no file progress for 20+ minutes, work incomplete) → auto-refire; coverage check (no lane idle with queue).
- **18:00 ET — Daily quality review:** Liz proofreads/QAs everything submitted that day against its laws and writes specific PARENT FEEDBACK (what was done well, what fell short, the exact correction) into each project's STATUS.md. Generalizable lessons are appended to the Blueprint and re-uploaded.
- **20:24 ET — Day-ahead prep:** tomorrow's plan drafted (no-decision prep).

## Blueprint upkeep duty (every agent)
- The Blueprint (~/workspace/BLUEPRINT/, Drive "Production Blueprint - Muse") is every agent's shared manual: read the file for your lane before starting.

Feedback is written where the next agent will read it BEFORE starting: the project's STATUS.md. A member that repeats a corrected mistake has failed to read its feedback — the review names it. Praise is specific or it is not given; criticism is specific or it is not given.

## TOKEN ECONOMY — METHODS OF RECORD (standing section · Kenneth's order, Sun Nov 15, 2026)

Kenneth's standing section, gathered in one place in the Blueprint and the clone doc on his direct order: the methods by which this floor saves tokens AND holds maximum output. **Governing constraint, over every method: savings live in how results are CARRIED, never in whether a check runs — output is never lessened, quality never traded. A method that cuts a check is not a saving; it is a defect.**

1. **One compact STATUS.md per production** — current state, exact paths/IDs, decisions and mappings, next step. Read it first; update it at each milestone. Never re-derive state from big source files or full logs when a status note exists.
2. **Probe, don't pour** — progress checks run as tail/grep/count one-liners; verdicts come back as compact summaries (decisive figures + the call), never as raw tables or full dumps poured into context. Read a big file once, extract what matters into the status note, work from the note.
3. **Report forms** — a completion is ONE line; a status is THREE lines (doing / completed / next); a gate ruling is the verdict + the 2–3 decisive numbers + conditions. Long-form belongs to gate packets and Kenneth's detailed phase/finish reports only. Anything Kenneth reads is plain words, full names and titles.
4. **One voice per event** — the owning desk reports an event; every other desk confirms absorption in one line or stays silent. Duplicate filings of one landing are a named token burn.
5. **Check before you send** — no escalation, ruling, or report fires before checking whether it already landed. Fire-critical text (captions, corrected files) rides INLINE; receivers report the md5 they actually read; on mismatch the inline text governs.
6. **Scripted pipelines over re-derived logic** — every repeatable pipeline (render drivers, edit builds, upload loops) is scripted and runs headless, logging to disk; a script re-run costs no reasoning, re-deriving its logic does.
